## 一、大方向

### 已确定的判断

- **2.0 不再加新模块**。3.0 留给 coding agent 和 app 发布。
- 2.0 的目标是：**"像一个正常的小产品，而不是课程作业"**。
- 不追求功能多，追求**用得顺、说得清、有记忆点**。

### 怎样才算"像产品"

不是功能多，而是**能看出开发者在某些地方做了选择**。

| 课程作业的样子 | 小产品的样子 |
| --- | --- |
| 功能都做了，但都很浅 | 少数功能做得深 |
| 换提示词算新功能 | 有专属界面、有状态、有边界 |
| 用户不知道怎么用 | 一进来就知道能干什么 |

## 二、要做的三件事（讨论中，未定稿）

### 1. 闲聊：插件化

把"插件"定义成：**一种有明确规则、有专属界面的对话模式**。

```
闲聊模块
├── 普通聊天（现在的样子）
└── 插件模式
    ├── 角色扮演   ← 先做这个
    ├── 模拟面试   ← 后面加
    └── 口语陪练   ← 后面加
```

**建议：先做 1 个插件做深，不要一次做 3 个浅的。**

### 2. 角色扮演（重点）

#### 已确定的决定

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| 要不要预设角色 | **要** | 好上手，而且预设本身就是内容，质量可控 |
| 角色要不要记住用户 | **要**（跨会话） | 沉浸感的关键 |
| 入口位置 | 未定 | 倾向放在闲聊模块里，不做独立标签 |

#### 角色来源

- **预设角色**：点了就用，手工调过的，质量有保证
- **自定义角色**：用户输入描述 → 联网搜索 → 生成角色档案 → 开始扮演

预设类型参考：

| 类型 | 例子 |
| --- | --- |
| 娱乐 | 孙悟空、毒舌室友、高冷侦探 |
| 有用 | 严格面试官、口语陪练、苏格拉底 |
| 功能 | 读书伴侣、树洞、吐槽对象 |

#### 自定义角色的流程

```
用户输入"我想扮演孙悟空"
  → web_search 搜角色资料
  → 模型整合成"角色档案"
  → 存起来，作为后续对话的 system prompt
  → 开始角色扮演
```

#### 三个必踩的坑及对策

| 坑 | 对策 |
| --- | --- |
| 搜索结果不等于人设，模型会念百科 | 要求转成**第一人称自述**，不能照抄资料 |
| 聊几轮后跑调，回到默认 AI 腔 | **每轮重申角色约束**，不只开头说一次 |
| 用户问"你真的是 X 吗"，角色出戏 | 约束在角色内回应，同时留一个"确实需要帮助时"的例外 |

#### 记忆分三层

| 层 | 记住什么 | 难度 | 必要性 |
| --- | --- | --- | --- |
| L1 角色记得自己 | 我是谁、说话风格 | 低（提示词带着） | 必须 |
| L2 角色记得这次对话 | 刚才聊了啥 | 低（对话历史） | 必须 |
| L3 角色记得上次对话 | 昨天聊过的 | 中 | 想要 |

**L3 的落地方式**：不存完整对话，存**"记忆摘要"**。

- 每次对话结束让模型总结一次，覆盖旧摘要
- 下次打开塞进 system prompt
- 存储小、上下文短、效果够

**关键设计**：界面上显示"它还记着你上次说的：……"，并允许删除某条记忆。
这是给用户控制感，也是"像产品"的细节。

#### 界面定稿（2026-11-11）

静态预览：`prototype/roleplay-preview.html`（用浏览器打开，或者看 `.png`）

**四个界面：**

1. **选角色**
   - 闲聊模块顶部有一条插件切换栏：`普通聊天 / 角色扮演 / 模拟面试 / 口语陪练`
   - 不做成独立标签页，插件是"玩法"不是"模块"
   - 预设角色分两组：**娱乐**（孙悟空、毒舌室友、高冷侦探）和**有用**（严格面试官、口语陪练、苏格拉底）
   - 玩过的角色卡片上显示"上次聊到 XXX"小标签，暗示角色有记忆
   - 最下面是虚线框的**进阶玩法**：`🔍 AI 帮我查` / `✍️ 我自己写`
   - 进阶玩法只在点了之后才展开两个选项，不干扰主路径

2. **AI 帮我查（等待过程）**
   - 分步骤显示进度，不是干转圈：
     `✓ 理解你要的角色 → ✓ 上网查资料（6 条结果）→ ◌ 整理成角色档案 → ○ 准备开场白`
   - 每一步下面显示具体细节
   - 页面下方**实时预告即将生成的角色档案**

3. **开聊前可以改**
   - 角色档案生成后先给用户看：名字、性格、说话方式、补充输入框
   - 两个按钮：`就这样，开始聊` / `换一个角色`
   - 这个"先看档案"的步骤让用户觉得控制权在自己手里

4. **角色对话**
   - 顶部紫色横幅：`正在和 🐵 孙悟空 聊天 · 换角色`
   - 下面灰色横幅：`↺ 他还记着你上次说的：准备考试、压力大 · 清空记忆`
   - 对话用角色口吻，不用 AI 腔

**通用约定：**

- 三种玩法最终都产出**同一份角色档案**格式（见下），后续流程共用一套
- 角色档案 = 名字 + 性格 + 说话方式 + 边界（什么不做）+ 开场白
- **档案不直接显示给用户**：生成成功后只显示「角色构建成功」+ 一句该角色的经典台词
  用户想改可以主动点开查看

**实现方式定稿：**

| 项目 | 决定 |
| --- | --- |
| 角色档案字段 | 名字、性格、说话方式、边界（不会做什么）、开场白 |
| 档案是否展示 | **不直接展示**，只给「构建成功 + 一句台词」；可主动查看 |
| 记忆更新频率 | **每 6 轮更新一次**（覆盖式，不是追加） |
| 记忆归属 | **按角色记忆**（不是按会话），同一角色多次聊天共用一份记忆 |
| 记忆长度 | 保持很短，200 字以内，每次覆盖旧摘要 |
| 记忆保存时长 | **永久** |
| 清空记忆 | **全清**，不做挑着删 |
| 预设角色存放 | **代码里的常量**，不进数据库 |
| 用户创建的角色 | 存数据库，用 `source` 字段区分来源 |
| 预设角色作者 | 用户本人写，AI 辅助整理格式 |

### 3. 智能出行：补"可信感"

不是加功能，是补三类信息：

- 用户不知道**结果准不准** → 说明数据来源和时效
- 用户不知道**能不能重新查** → 给明确的重新查询入口
- 用户不知道**为什么推荐这条** → 给推荐理由

## 三之二、还需要定的细节

以下是实现前必须先定下来的，不然做到一半会卡住：

### A. 角色档案的字段到底有哪些

现在预览里是：名字、性格、说话方式、不会做什么。
还需要想清楚：

- 要不要**开场白**（角色第一句话）？要的话谁写——预设你写，AI 生成的让模型写
- 要不要**头像**？预设可以用 emoji，自定义角色怎么办（自动选一个？让用户选？）
- 要不要**标签**（如"狂妄·直爽"）？谁生成

### B. 记忆的具体规则

- 记忆摘要**什么时候生成**？
  - 每轮都更新（成本高）
  - 会话结束时更新（但会话结束的判定是什么？）
  - 用户主动点"结束"时更新
  - 建议：**每 6 轮更新一次 + 用户手动结束会话时更新**
- 记忆**存多久**？永久保留，还是保留最近 N 条？
- 一个角色一份记忆，还是每个会话一份？
  - 建议：**一个角色一份**（同一个人和孙悟空聊过三次，孙悟空记得所有）
- "清空记忆"是清全部还是可以选某条删掉？

### C. 预设角色谁来写

- 你写，还是我先起草一批你改？
- 第一批做几个？（建议 6～8 个）
- 每个角色的档案要多详细？

### D. 数据存在哪

- 新建一张表 `role_play_chats`？还是复用现有的 `sessions`？
- 角色档案存表里还是存配置文件？
  - 建议：**预设角色存代码里的常量**（改了代码就生效，好维护）
  - **自定义角色存数据库**（用户创建的）

### E. 和现有闲聊怎么共存

- 现有的闲聊会话列表，要不要也显示角色扮演的会话？
- 一个角色会不会变成"一个会话"，还是"角色是角色，会话是会话"？
- 建议：**左侧列表按会话显示**，会话上面标注用的是哪个角色

### F. 出错怎么办

- AI 搜不到资料怎么办？（比如用户输入一个不存在的名字）
- 生成的角色档案质量太差怎么办？（给不给"重新生成"）
- 角色聊着聊着出戏了怎么办？（要不要加个提示词兜底）

**新增文件：**

| 文件 | 作用 |
| --- | --- |
| `modules/roleplay/presets.py` | 预设角色数据，现在放了 3 个示例 |
| `modules/roleplay/prompts.py` | 把角色档案拼成提示词 |
| `modules/roleplay/stream.py` | 角色对话的流式出口 |
| `databases/db_roleplay.py` | 记录"哪个会话是哪个角色" |

**修改文件：**

| 文件 | 改了什么 |
| --- | --- |
| `api/main.py` | `/chat` 加 `role_id` 参数；新增 `/roleplay/roles`、`/roleplay/start`、`/roleplay/session/{id}` |
| `core/db.py` | 建表列表加了一行 `db_roleplay` |

**新增表：** `role_play_sessions`（会话 → 角色）

**接口：**

| 接口 | 作用 |
| --- | --- |
| `GET /roleplay/roles` | 列出预设角色 |
| `POST /roleplay/start` | 选角色开始，返回会话 id 和开场白 |
| `GET /roleplay/session/{id}` | 刷新页面后查这个会话是哪个角色 |
| `POST /chat`（带 `role_id`） | 角色对话，流式返回纯文本 |

**预设角色怎么写：** 打开 `modules/roleplay/presets.py`，照着里面 3 个示例复制一份，
改字段即可。现在只有孙悟空、毒舌室友、严格面试官三个占位。

**已验证：**

- 选角色、开场白、角色对话正常
- 普通闲聊没有被改坏
- 用错角色去聊会返回 400
- 拿别人的会话 id 会返回 404
- Docker 8080 和本机 8091 都测过

**还没做的：**

- 第 3 步：自定义角色（AI 搜索生成、用户手写）
- 前端界面（插件条、角色卡片、聊天界面）

### 第 2 步：角色记忆（后端已完成）

**新增文件：**

| 文件 | 作用 |
| --- | --- |
| `modules/roleplay/memory.py` | 每 6 轮把对话压缩成 200 字以内的摘要 |

**新增表：** `role_play_memories`（租户 + 角色一份记忆，永久保存）

**新增接口：**

| 接口 | 作用 |
| --- | --- |
| `GET /roleplay/memory/{role_id}` | 查这个角色记得什么 |
| `POST /roleplay/memory/clear` | 清空这个角色的记忆 |

**规则：**

- 每聊 6 轮，后台自动整理一次，不让用户等
- 摘要在 200 字以内，覆盖旧摘要，不是越写越长
- 按角色存，换会话也能记住
- 清空是全清，不做逐条删除
- `roleplay/start` 和 `roleplay/session/{id}` 会带上 `memory` 字段

**已验证：**

- 连续聊 6 轮后生成摘要，内容能抓住用户信息和角色承诺
- 清空后记忆为空，新会话不残留
- Docker 8080 接口正常

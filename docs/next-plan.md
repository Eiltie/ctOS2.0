最后更新：2026-11-11

## 一、大方向

### 已确定的判断

- **2.0 不再加新模块**。3.0 留给 coding agent 和 app 发布。
- 2.0 的目标是：**"像一个正常的小产品，而不是课程作业"**。
- 不追求功能多，追求**用得顺、说得清、有记忆点**。

### 怎样才算"像产品"

不是功能多，而是**能看出开发者在某些地方做了选择**。

| 课程作业的样子 | 小产品的样子 |
| --- | --- |
| 功能都做了，但都很浅 | 少数功能做得深 |
| 换提示词算新功能 | 有专属界面、有状态、有边界 |
| 用户不知道怎么用 | 一进来就知道能干什么 |

## 二、要做的三件事（讨论中，未定稿）

### 1. 闲聊：插件化

把"插件"定义成：**一种有明确规则、有专属界面的对话模式**。

```
闲聊模块
├── 普通聊天（现在的样子）
└── 插件模式
    ├── 角色扮演   ← 先做这个
    ├── 模拟面试   ← 后面加
    └── 口语陪练   ← 后面加
```

**建议：先做 1 个插件做深，不要一次做 3 个浅的。**

### 2. 角色扮演（重点）

#### 已确定的决定

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| 要不要预设角色 | **要** | 好上手，而且预设本身就是内容，质量可控 |
| 角色要不要记住用户 | **要**（跨会话） | 沉浸感的关键 |
| 入口位置 | 未定 | 倾向放在闲聊模块里，不做独立标签 |

#### 角色来源

- **预设角色**：点了就用，手工调过的，质量有保证
- **自定义角色**：用户输入描述 → 联网搜索 → 生成角色档案 → 开始扮演

预设类型参考：

| 类型 | 例子 |
| --- | --- |
| 娱乐 | 孙悟空、毒舌室友、高冷侦探 |
| 有用 | 严格面试官、口语陪练、苏格拉底 |
| 功能 | 读书伴侣、树洞、吐槽对象 |

#### 自定义角色的流程

```
用户输入"我想扮演孙悟空"
  → web_search 搜角色资料
  → 模型整合成"角色档案"
  → 存起来，作为后续对话的 system prompt
  → 开始角色扮演
```

#### 三个必踩的坑及对策

| 坑 | 对策 |
| --- | --- |
| 搜索结果不等于人设，模型会念百科 | 要求转成**第一人称自述**，不能照抄资料 |
| 聊几轮后跑调，回到默认 AI 腔 | **每轮重申角色约束**，不只开头说一次 |
| 用户问"你真的是 X 吗"，角色出戏 | 约束在角色内回应，同时留一个"确实需要帮助时"的例外 |

#### 记忆分三层

| 层 | 记住什么 | 难度 | 必要性 |
| --- | --- | --- | --- |
| L1 角色记得自己 | 我是谁、说话风格 | 低（提示词带着） | 必须 |
| L2 角色记得这次对话 | 刚才聊了啥 | 低（对话历史） | 必须 |
| L3 角色记得上次对话 | 昨天聊过的 | 中 | 想要 |

**L3 的落地方式**：不存完整对话，存**"记忆摘要"**。

- 每次对话结束让模型总结一次，覆盖旧摘要
- 下次打开塞进 system prompt
- 存储小、上下文短、效果够

**关键设计**：界面上显示"它还记着你上次说的：……"，并允许删除某条记忆。
这是给用户控制感，也是"像产品"的细节。

### 3. 智能出行：补"可信感"

不是加功能，是补三类信息：

- 用户不知道**结果准不准** → 说明数据来源和时效
- 用户不知道**能不能重新查** → 给明确的重新查询入口
- 用户不知道**为什么推荐这条** → 给推荐理由

## 三、待讨论的问题

1. **角色扮演的开始方式**：先选角色再聊，还是先说想跟谁聊再自动识别？
2. **插件的入口**：放在闲聊模块里（倾向），还是做成独立标签？
3. **其他插件**：模拟面试、口语陪练什么时候做、做成什么样？

---

## 四、明确不做的事

为了不把 2.0 拖成 3.0：

- 不加新的独立大模块
- 不做 coding agent（留给 3.0）
- 不大改视觉（三套主题已经够了，边际收益低）
- 不为了"功能数"做浅功能
